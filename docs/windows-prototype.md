# Windows shared-core prototype

The migration has executable development code in `core/` and a typed desktop workbench in `desktop/`. The retained `--mock-pipe` namespace uses protocol v1; the independent `--serve` host uses protocol v2. This is **partial P0/P1**, not a usable Windows VPN, accepted installer, or replacement for the Ruby backend. No complete OpenSpec implementation task is marked done solely from this prototype.

## Implemented isolation boundaries

- Pure domain transitions use an injected monotonic time, distinguish attachment/unknown from canaries, retain live original paths, require exact-path rebuild before selected-city fallback, validate generation/epoch/boot/operation/instance/front evidence and reserve peers atomically.
- Readiness has the same IP-or-HTTPS liveness definition as Ruby. New PQ transactions and fallback require complete readiness; an original data path can remain DNS-degraded. This is tested across 32 shared canary combinations.
- The command protocol uses 4-byte little-endian JSON frames, a 65,536-byte cap, explicit major/boot IDs, typed commands and bounded request IDs. A mock operation cache reconciles a lost response within its capacity/TTL. Version 1 retains mock-only operations; version 2 uses explicit secret input types and public output DTOs.
- The Windows mock pipe uses an explicit current-user DACL, rejects remote connections, checks SID/session via client impersonation and server-process token, and limits each session to five seconds and sixteen requests. The pipe has a separate mock namespace and the agent runs independently of the UI. A first-instance mutex/pipe prevents duplicate owners.
- The desktop reads real host snapshots, official catalogue views, favorite-city settings, account/device operations and bounded diagnostic exports. It has no arbitrary renderer shell or path commands. Missing data is displayed as unknown. A packaged build may start its verified per-user host independently of UI lifetime; the unsigned runtime manifest must match a compile-time digest in the UI. The agent independently pins the official engine bytes.
- Every native bridge request first verifies the backend protocol, full source SHA, package version and boot identifier. An old v2 host without source identity is rejected before credentials or mutations are sent; an upgrade does not automatically stop another existing host. Diagnostics copy only the backend's current public report path through the Windows Unicode clipboard. The renderer supplies an expected report basename, never arbitrary clipboard text or a filesystem path. A newly requested export cannot copy the prior report; clipboard contention preserves the file and offers an explicit retry.
- The live host starts only a fixed REJECT front. `Connect` and full testing remain explicitly blocked until the owned worker, physical-egress proof, selector/persistence transaction and recovery acceptance are complete. Front-process readiness is not tunnel readiness. Imported keys are bounded and validated using X25519, stored through DPAPI and read back; import never registers a device.
- Metadata/account requests use only an explicitly configured loopback bootstrap proxy, strict TLS and bounded bodies/deadlines. Mutations have no blind retry after an unknown result, and current-device removal is blocked. Logging, API I/O, settings writes and reports are separate from the hardware state-owner thread. Reports include only validated event fields and public snapshots; linked/reparse log files are rejected.
  Account authentication has a 30-second budget; an account snapshot shares a separate 30-second budget across both GETs and any one token renewal. Proxy negotiation and TLS handshake use the remaining request budget, without an earlier four-second connection cutoff. These bounds allow slower bootstrap exits without extending the 12-second device/voucher mutation deadline or adding automatic mutation retries.
- IPv4 quick checks use at most four ICMP lanes within one city, with a 1200 ms native timeout per echo, 256-target cap and 45-second batch budget. They neither start a Mihomo worker nor use a device key. Cancellation retains the operation until every started call returns. Late/invalidated observations are discarded, not counted as failed relays. Automatic maintenance checks two rotating targets per city, the selected city every 30 seconds and other favorites every three minutes, sequentially. Physical notifications, binding changes, evidence gaps and catalogue refresh invalidate cached RTTs. Public backup ranking expires after three minutes and never means tunnel Ready.

- A worker acquires a machine-wide presence lease derived from its actual X25519 public key. The allowlisted child inherits that lease, so dropping the parent handle does not immediately permit a competing adapter worker. Normal retirement still requires confirmed termination of the entire owned Job. This excludes adapter workers across user sessions and test scopes; it does not control other VPN applications or another computer using the same identity.

`adapter-agent --verify-tunnel --relay <catalogue-hostname> --transport ipv4|ipv6|ss` is an explicit maintenance check using the already imported identity and cached official catalogue. It validates the packaged runtime, starts one worker on isolated loopback ports, measures IP/inner-DNS/HTTPS, fences the result against physical observation and domain identity, and confirms owned-worker retirement. SS prefers the relay's explicitly published extra IPv4 inlet. These dedicated addresses accept all nonzero ports; the deterministic default 20484 preserves this project's macOS policy and is not an official fixed-port requirement. Without an extra IPv4 inlet it uses the first validated primary-address SS port range. An explicit `--port` in the primary range selects that primary path for comparison; other nonzero ports require a published extra inlet. No extra IP is invented. The public result includes outer address, port and inlet kind. See the pinned [official selector](https://github.com/mullvad/mullvadvpn-app/blob/2026.5/mullvad-relay-selector/src/relay_selector/endpoint_set.rs) for the two endpoint contracts. It never selects a front or modifies global routes/proxy settings. Its public output explicitly marks physical packet capture as `NOT_RUN`; a successful canary is not complete Windows deployment or physical-egress acceptance. DNS authenticates its original connected SOCKS peer before sending bytes and checks the retained worker process after the nonce-validated response. A normal server FIN can remove the ESTABLISHED table row; that row is not required after a complete response. The socket is never reconnected or replaced, and cancellation, epoch, freshness and cleanup gates still apply.

## Validation commands

```
ruby -I . -I daemon -e 'ARGV.each { |f| require File.expand_path(f) }' daemon/test_*.rb
ruby scripts/test-shared-contract.rb
cargo test --manifest-path core/Cargo.toml --locked
cargo check --manifest-path core/Cargo.toml -p adapter-platform --features windows-api-check --tests
cd desktop && npm ci --ignore-scripts && npm run build
```

The API-signature feature checks Windows FFI declarations without executing Windows. It does not replace Windows-hosted tests. The new CI matrix runs shared tests on Linux/macOS/Windows, checks Swift/Ruby compatibility on macOS and builds the Windows Tauri UI separately. CI must pass for the exact pushed source; adding a workflow is not a passing run.

## Remaining gates

P0: full event-sequence replay and old Swift decoding, generated shared UI types and measured controlled scheduling baselines. P1: Windows identity-negative/session/lifecycle tests, Job Object supervision, bounded graceful stop, complete installer and actual WebView2 acceptance. P2/P3: physical attachment and explicit egress, DPAPI/atomic persistence, Mihomo front/worker/controller protection, metadata/account clients, full UI features and accepted protection. P4/P5: actual install/upgrade/routing/PQ and then authorized macOS handover. Mock capability failures must not be changed to successful connection claims as placeholders.

Synthetic fixtures contain no real identity, account, live logs or production paths. Live imports and account operations are separate, explicitly authorized runtime actions. The old macOS candidate and installed version remain separate. See [packaging gates](../packaging/windows/README.md), [core notes](../core/README.md) and the [source specifications](../openspec/changes/windows-shared-core/tasks.md).

Native pipe responses require a bounded ResponseAck frame carrying the request ID before the server advances or closes the session. The original five-second session deadline bounds acknowledgement waits. The debug stdio transport does not require this pipe-specific close acknowledgement.

Both exact-original rebuilds and fallback candidates must register a new candidate attempt before execution. Completion evidence must match that registered path/instance and attempt, be observed after its start and no later than the completion clock, and be at most five seconds old. Busy/local failures clear registration; a deferred retry receives a new attempt ID. The 45-second recovery budget gates starting work. Already-started work may finish only before its 90-second hard attempt deadline, including failure outcomes. Ninety seconds is a prototype safety ceiling, not a measured performance promise. The future engine executor must cancel and reclaim expired work; domain rejection alone is not process supervision.
