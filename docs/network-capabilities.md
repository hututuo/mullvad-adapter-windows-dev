# 通道能力与数据来源

## 数据来源

| 数据 | 来源与含义 |
|---|---|
| relay 名称、地点、active、公钥、IPv4/IPv6、SS extra 地址、WG/SS端口范围 | 官方 HTTPS `/app/v1/relays`；active 是目录标记，不是当前可达性 |
| 客户端私钥与公钥 | 本地安全生成；设备登记及隧道地址由官方设备 API 返回 |
| SS aes-256-gcm 与公共密码 mullvad | 上游协议常量，不是个人账号密码 |
| extra SS 端口 20484 | 本地选择值，仅用于 API 发布的 extra 地址；主地址必须满足 API 端口范围 |
| 25秒保活、MTU、回退预算、路由规则 | 明确的客户端策略，不应伪称 API 数据 |
| 本机网卡/路由、Clash端口与节点、进程 | 本机观测或用户配置，不复用开发者机器的值 |

Windows 启动先使用有效本机缓存，物理网络稳定后在独立线程自动刷新官方目录，
成功后每 6 小时更新。失败保留缓存，按 30、60、120、240、300 秒退避（封顶）；已确认的物理断网暂停请求，
连续失败期间仅允许一次稳定恢复提前唤醒。手动更新共用单个在途任务，不占用账号或隧道队列。
新缓存保存实际获取时间，旧缓存没有时间则如实显示；过期目录不是当前可达性的证明。
更新不会重启健康 worker、主动探测备用 WG，或清空当前恢复轮的失败/时间预算。

主界面“查看更新内容”区分检查成功、目录确实变化和首次无基线；单列检查时使用节点的
SS 地址增删、主地址 SS 端口、IPv4/IPv6、公钥摘要和官方 active 状态。目录排序、重复
地址和等价 IP 表达不算参数变化。详情有数量及截断说明；状态读取仅复制预计算结果。
缓存写盘失败时新目录仍在内存生效，旧磁盘数据保留，并单独显示保存警告。完整公开
目录差异留在本地轮转日志；导出的共享诊断只保留变化计数、当前变化状态及字段名，
不附带差异中的地址、公钥或其他原始内容。目录没变不能排除服务端或网络路径故障。

## 真实生产路径与限制

当前 Windows 产品的连接路径是 WireGuard over Shadowsocks，外层经物理网卡
绑定的 UDP carrier；carrier 的 SOCKS TCP 控制连接不等于承载业务的 UDP-over-TCP。
Direct IPv4/IPv6 配置生成器存在，但产品自动恢复尚不选择这些路径。
QUIC、UDP-over-TCP、LWO 未接入，不能将官方 App 的支持矩阵套用到本软件。
Windows 对必需多跳/PQ采取显式不支持，不能悄悄降低保护。Mac 旧实现的能力与
验收独立，不能因此宣称 Windows 等价。IPv6、MTU与大流量仍需单独真机验收。

Windows 可从本机 Clash 实际配置及受限的本地 provider 缓存导入一个独立 SS 叶节点，
作为可选的隧道承载。策略为仅直连、优先直连后链式备用、固定链式。默认自动策略在
未保存独立节点时只尝试原有直连；不会猜测或免费生成备用节点。首阶段仅支持 IPv4
出站、无插件的 aes-128-gcm / aes-256-gcm / chacha20-ietf-poly1305 SS UDP。
不支持的节点、IPv6 literal、歧义名称、越界 provider 路径不列为可用；导入绑定配置摘要，
配置变化后必须重新读取。密码不进入 renderer、日志、报告或公开配置，在本机 DPAPI 保存。

链式路径为 WG → Mullvad SS → 独立 SS → 自持认证 carrier → 物理网卡。物理 socket
和 route witness 指向独立 SS 的真实 IPv4；最终业务选择仍只有 Mullvad。不会借用外部
Clash 的通用 SOCKS 端口冒充物理绑定证据，也不改用户的 Clash 选择组。域名经有界的
系统解析线程解析后，仅接受公网 IPv4。Windows 从唯一的实际本机 Clash 配置定位
命名管道，优先用只读 `/dns/query` 获取真实 A/CNAME，再尝试系统解析；HTTP 控制
端点不用于这条引导路径，不发送控制凭据。总调用仍有 4 秒期限；本机控制查询与系统解析各用一个固定线程及有界队列，
系统解析卡住不会堵死下一次本机控制查询。
校验问题名称及别名链、响应大小与公网地址，每个新 worker 重新解析。既有 worker
固定自己的实际 socket 目标，不把解析 IP 写死在保存的节点中；假 IP、空响应或
超时明确报备用节点解析失败，不计为 Mullvad 节点失效。
仍存活或待恢复的链式原路径不允许后台更换上游，需先显式断开。独立节点本身必须
支持 UDP，链式不是 UDP-over-TCP，不能据此承诺能通过全面 UDP 封锁。

对称型 NAT 不等于必然连接失败：客户端主动连接固定公网 relay 与 P2P 打洞
不同，出站 UDP 及相同目标的回包仍可能可用。25秒 WireGuard 保活用于维护
闲置映射，不解决禁 UDP。SS 也不能突破全面 UDP 丢弃；需要真实 TCP 传输实现
及服务端兼容验收。不能靠改端口、增加并发或更换节点来宣称解决。

账号控制面在未配置代理时显式通过系统路由的 HTTPS 访问，忽略环境代理，保留
证书校验、禁重定向、总超时与响应大小上限。系统路由不是物理网卡绑定；外部
TUN需有独立API规则。配置了本机代理时不会静默回退或重放设备写操作。受限
网络可能仍需独立普通节点或后续 API bridge，不能承诺无节点新用户必定直连成功。

## 稳定与恢复

保留物理断网暂停、稳定恢复2秒后验证原路径、原路径重建后才同城备选的策略。
失败 active Verify 有15秒重试间隔，避免恢复不可启动时每个主循环都重测。
进程创建锁排队每10ms检查取消/截止/路由；持锁后再检查。CreateProcessW本身
不可取消，失败清理仍有 carrier 与进程树的独立预算。300秒是启动恢复新尝试的
预算，不是端到端恢复保证；DNS/IP/域名HTTPS分别有2/8/12秒接受预算，
证据过期时还可能追加一次有界重测，不能据此承诺完整检查固定14秒内结束。
正常健康检测结束后间隔30秒。
这些是源码预算，不是这次故障注入实测。没有自动睡眠、物理断网或电源策略测试。

接口参数通知先在原有本地采样线程核对完整字段；只有接口Metric变化时，保留现有
通道、在途检测及稳定计时，不据此显示网络恢复或反复启动完整检测。核对期间暂缓
采用检测结果和启动新连接，最多等待原有两秒证明窗口；真正连接状态、MTU等参数
变化或读取失败仍使旧验证失效。地址、路由、接口增删通知与绑定/源地址/同socket
证明继续严格校验。Metric影响系统选路，豁免的是已约束到物理接口的通道上、其他
字段未变的接口Metric通知，并不是宣布所有优先级变化都不影响网络。

Windows 保留用户连接的城市及显式节点意图。一轮恢复耗尽后，只要自动恢复仍启用，
按 60、180、300 秒（封顶）间隔开启下一轮；每轮仍遵守原次数和时间上限，不会因
循环 tick 或目录刷新无限续期。已确认断网时不发送新连接，网卡稳定后才继续。
本地启动失败可以退避再试，但不计作节点失效；身份/保护配置错误和清理不确定
不会自动重试。成功验证会取消等待；“断开连接”会清除恢复意图，界面提供倒计时、
停止自动恢复及立即重试。以上属于恢复策略，实际故障恢复耗时仍需现场证据。

用户连接请求优先于自动 ICMP 维护。后台 Ping 尚未退出时保留一次连接意图，
先取消维护，收到所有原生调用完成的回执后才释放登记位并开始连接。期间可以
取消该意图；断开和退出也会清除它。不会提前释放锁、并行使用同一设备身份，
也不为账号或设备写操作提供自动重试。

### 直连优先恢复与备用路线

第一次确认的数据面失败保留现有 worker，约2秒后复测，连续两次失败才启动恢复；
本机离线、证据过期、取消和本地错误不计节点失败。后端仍健康时优先修复本地 front。
恢复先串行重建原节点原 SS，失败清理后间隔1秒、5秒短重试；再试原节点最多三个
备用 SS，优先本周期未试过的入口，再以真实成功历史排序。最多四个其他同城节点，每个最多两个 SS。
每轮使用固定节点集合；所有直连选择实际用尽后才进入链式，不再逐入口交错。
整体新尝试预算300秒，单次仍有90秒硬上限及独立清理预算，不是恢复耗时保证。
本机历史只帮助排序，不取代新鲜健康检查或官方目录授权。

候选池同时包含官方专用地址及主地址 SS 端口范围；保留 Windows 已有的专用 UDP/443
选择。完整池并不意味着并行或全量探测，每轮启动限额仍生效。跨轮已试集合与评分
一起加密保存在 RecoveryHistory；同目录刷新和重启保留，部分增删仅裁剪撤下的元组，
公钥变化才作为新 peer。目录变化不能退还本轮已用预算。原入口短重试是明确例外；
备用池全部实际尝试过后才循环，取消/本地失败不消费入口。保存队列合并为最新完整
快照，不因为通知队列已满而丢掉最新记录；磁盘 I/O 不占用连接或状态锁。

链式从实际 Clash 配置和受限的本地 provider 缓存自动准备，按节点名称提示优先
美国、新加坡，再英国；实际物理 UDP 收发验证决定能否采用。后台不启动第二条同
身份 WG。主页面一个“测试备用路线”完成准备、完整隧道流量验证和原路线恢复，
不要求逐个节点操作。高级设置可固定兼容节点，偏好保存在本机策略中。
完整试切在同一节点最多尝试两个授权 SS 入口，第二次仍失败才恢复原路径。
自动选择时，只有确认恢复了测试前的直连、身份/进程/配置意图均未变化，才续测下一
独立候选；最多六个完整候选，420秒后不再开始新候选。手动固定节点不自动跳到别的
独立代理。通过完整隧道验证的代理及时间单独加密保存；轻量准备、失败测试和重启
不能覆盖这份快照。后台维护优先保留仍匹配的已验证配置；快照是成功历史，不代表
当前一定可用。原路径复验与实际重建在主页使用不同阶段。
Auto链式连接后120秒开始串行尝试回到直连，失败恢复刚才的链式，并按5/15/30分钟
退避；固定链式策略不主动回直连。所有试切均先确认旧worker停止，不承诺无损。
当前阶段、relay/SS、耗时、下一步、手动重试与停止都显示在城市主页。

## 启动与系统流量接入

Windows 默认在启动后连接已选城市；优先使用仍被当前目录授权的上次节点和 SS 入口，
完整验证后才提交 front。可在连接设置关闭；本次启动中显式断开/取消会撤销启动意图。
启动不会创建身份或替用户开启系统代理/TUN，也不会在退出后私自更改 Clash 规则。
外部 Clash 已启用所选配置和系统代理/TUN时，命中本机节点的流量才进入适配器。
隧道未就绪或重建时 front 拒绝转发，不提供 DIRECT 回落；已有长连接可能中断，不能
宣称无损切换或系统级 kill switch。国内/局域网直连与用户其他节点继续按 Clash 规则。

Clash Verge 2.5.8 服务模式会覆盖 YAML 中的 sidecar 控制管道。Windows 接入只在
当前用户 SID 摘要匹配时解析官方 sidecar-release / production 管道对；仅一个存活
才使用，两者同时存在或权限错误则明确失败。一次接入事务固定控制端点，不跨端点
重放写操作，不转向 HTTP 或发送 HTTP secret，也不更改 Clash 的服务模式。
命名与模式切换依据为 [Clash Verge v2.5.8](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.8/src-tauri/src/core/manager/state.rs)
及其固定 [service-ipc v2.7.6](https://github.com/clash-verge-rev/clash-verge-service-ipc/blob/v2.7.6/src/core/paths.rs)。


### 本地观测故障与启动等待

本地 listener 连接失败、SOCKS 初始握手不响应或所属进程不可用，不证明远端
Mullvad/SS节点坏了。没有独立成功数据探测时，这些结果保留分阶段诊断并返回
本地故障，不生成全失败节点样本；已有健康流量则沿用IP或HTTPS成功的判断。
持续本地故障走原有原路径重建，不跳过身份独占、证据时效或进程归属校验。

front/worker启动保留15秒总接受预算；控制HTTP、mixed端口连接、链式地址解析
共享其剩余时间，不能到截止前再开启全长等待。后续正常控制请求使用新的单次预算。
原生进程归属/网卡查询仍不能强行中止，已启动探测线程须完成回收，进程清理另有
独立预算。因此这些限制不是操作系统级实时保证，也不代表新版本已实机替换。
