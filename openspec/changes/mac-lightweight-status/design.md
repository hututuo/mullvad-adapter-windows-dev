# Design

Publish immutable JSON in memory once per second. Capture uses try_lock on state and operation locks, skips contention, retains the previous publication without renewing its capture time, and performs no disk/network logging. GET /status reads the publication without those locks or JSON-encoding live state. Maximum publication age is 3 s; older/missing data returns a typed 503 instead of stale ready. Age and capture duration are numeric headers. Internal control snapshots and atomic profile commit remain authoritative and unchanged.

Swift status reads use a dedicated ephemeral direct-loopback session, without proxy, cache, cookies or credential storage; other requests retain their existing session/authorisation. Five-second transport timeout stays unchanged. Status polling and city polling run independently; manual snapshot refresh updates status before supplementary requests complete. Legacy servers lacking publication headers remain supported. UI conservatively adds request/scheduling time to observation age and rejects expired delivery. UI records publication age/capture duration when available and distinguishes publication delay from network/tunnel failure.
